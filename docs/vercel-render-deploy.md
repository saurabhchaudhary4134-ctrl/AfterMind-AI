# AfterMind AI — Vercel + Render + Neon Deployment Guide

This guide covers deploying the full AfterMind AI stack using free-tier services:

| Layer | Service | Plan |
|-------|---------|------|
| Frontend (Next.js) | Vercel | Free (Hobby) |
| Backend (FastAPI) | Render | Free (Web Service) |
| Database (PostgreSQL) | Neon | Free (0.5 GB storage, 1 branch) |

---

## Prerequisites

- GitHub account (both Vercel and Render connect via GitHub OAuth)
- The project pushed to a GitHub repository
- No Docker required — both platforms build from source

---

## Step 1 — Neon PostgreSQL

1. Go to [neon.tech](https://neon.tech) and create a free account.
2. Create a new project (region closest to your Render service — e.g. `us-east-2`).
3. From the **Connection Details** panel:
   - Select **Pooled connection** and **Node.js** driver.
   - Copy the connection string. It looks like:
     ```
     postgresql://user:password@ep-xxx-yyy.us-east-2.aws.neon.tech/neondb?sslmode=require
     ```
4. Replace `postgresql://` with `postgresql+psycopg2://` for SQLAlchemy:
   ```
   postgresql+psycopg2://user:password@ep-xxx-yyy.us-east-2.aws.neon.tech/neondb?sslmode=require
   ```
5. Keep this URL — you will paste it into Render as `DATABASE_URL`.

**Important:** Neon's free tier uses connection pooling via PgBouncer. The `?sslmode=require` suffix is mandatory.

---

## Step 2 — Render (Backend API)

### 2a. Deploy via Blueprint (recommended)

The `render.yaml` in the project root automates service creation.

1. Go to [render.com](https://render.com) → Dashboard → **New** → **Blueprint**.
2. Connect your GitHub repository.
3. Render finds `render.yaml` and creates the `aftermind-api` service automatically.
4. After creation, go to the service → **Environment** and set these **manually** (they are marked `sync: false`):

| Variable | Value |
|----------|-------|
| `DATABASE_URL` | Your Neon URL from Step 1 |
| `CORS_ORIGINS` | Your Vercel URL (set this after Step 3; use a placeholder like `https://aftermind-ai.vercel.app` for now) |

   `SECRET_KEY` is auto-generated by Render (configured in `render.yaml` as `generateValue: true`).

### 2b. Manual deploy (alternative)

1. Render Dashboard → **New** → **Web Service** → connect your GitHub repo.
2. Configure:
   - **Root Directory:** `services/api`
   - **Runtime:** Python 3
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `python -m alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
3. Set all environment variables from the table in §2a plus the defaults in `.env.example`.

### 2c. Verify the backend

Once deployed, visit:
```
https://aftermind-api.onrender.com/api/v1/health
```
Expected response:
```json
{"status":"ok","service":"aftermind-api","environment":"production","version":"0.1.0"}
```

Note the service URL — you need it for Step 3.

**Free tier cold starts:** Render free web services spin down after 15 minutes of inactivity. The first request after idle takes ~30 seconds. Acceptable for a startup MVP.

---

## Step 3 — Vercel (Frontend)

### 3a. Import the project

1. Go to [vercel.com](https://vercel.com) → **Add New Project** → **Import Git Repository**.
2. Select your GitHub repo.
3. Vercel detects the `vercel.json` in the root and automatically sets:
   - **Root Directory:** `apps/web`
   - **Framework:** Next.js
   - **Build Command:** `npm run build`

### 3b. Set environment variables

In the Vercel project settings → **Environment Variables**, add:

| Variable | Value | Scope |
|----------|-------|-------|
| `NEXT_PUBLIC_API_URL` | `https://aftermind-api.onrender.com/api/v1` | Production |
| `NEXT_PUBLIC_API_URL` | `http://localhost:8000/api/v1` | Development |

⚠️ `NEXT_PUBLIC_*` variables are baked into the JavaScript bundle at build time. After changing this variable in Vercel, you must **Redeploy** for the new URL to take effect.

### 3c. Deploy

Click **Deploy**. Vercel runs `npm install` then `npm run build`. First deploy takes ~2 minutes.

Your frontend URL will be `https://aftermind-ai.vercel.app` (or similar — note it for the next step).

---

## Step 4 — Wire up CORS

Now that you know the Vercel URL, update the `CORS_ORIGINS` variable in Render:

1. Render Dashboard → `aftermind-api` → **Environment** → edit `CORS_ORIGINS`
2. Set to your Vercel URL: `https://aftermind-ai.vercel.app`
3. If you have a custom domain, add it as a comma-separated second value:
   `https://aftermind-ai.vercel.app,https://www.yourdomain.com`
4. Render automatically redeploys on env var changes.

---

## Step 5 — Verify end-to-end

1. Open `https://aftermind-ai.vercel.app`
2. Register a new account.
3. Create a decision, add Decision DNA, create a scenario, run a simulation.
4. Verify results are persisted — log out, log back in, open the same decision.

### Smoke-test checklist

- [ ] `GET /api/v1/health` → 200
- [ ] `POST /api/v1/auth/register` → 201 with tokens
- [ ] `POST /api/v1/auth/login` → 200 with tokens
- [ ] `GET /api/v1/me` → 200 with user profile (proves JWT works)
- [ ] `POST /api/v1/decisions` → 201 (proves DB connection works)
- [ ] `POST /api/v1/simulations` → 202/200, status `completed` (proves simulation engine works)

## Architecture notes

### Why `SIMULATION_SYNC=true` on Render free tier

Render free tier provides a single web process with 512 MB RAM. Redis (required by Celery) is a paid Render add-on. With `SIMULATION_SYNC=true`, simulations run synchronously inside the web request — the API returns `202 Accepted` and the result is ready immediately. This is fully functional; all tests pass with `SIMULATION_SYNC=true`.

To add Celery workers later: provision a Render Redis instance (paid), set `SIMULATION_SYNC=false`, and add a `worker` service to `render.yaml`.

### `NEXT_PUBLIC_API_URL` is build-time

Next.js bakes `NEXT_PUBLIC_*` variables into the JavaScript bundle during `npm run build`. Changing this variable in Vercel requires a **redeploy** — a runtime environment override does not work.

### Neon connection pooling

Neon's free tier routes connections through PgBouncer (connection pooler). The `psycopg2-binary` driver handles this correctly with the pooled connection URL. The `?sslmode=require` suffix is required by Neon.

### Cold start on Render free tier

Render free web services hibernate after 15 minutes of inactivity. The first request after hibernation takes ~30 seconds (loading Python, importing NumPy/SciPy/Pandas). Subsequent requests are fast. To prevent hibernation, configure an external uptime monitor (e.g. UptimeRobot free tier pinging `/api/v1/health` every 10 minutes).
